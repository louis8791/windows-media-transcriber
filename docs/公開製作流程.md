# 公開製作流程

本文件以去識別方式描述可重現的製作流程。讀者應使用自己的媒體、自己的執行環境與自己的本機設定重建流程；本文不提供任何私人檔名、逐字內容、絕對路徑、模型二進位檔或本機秘密。

## 流程總覽

```text
input_audio
  → 5 分鐘實體分段
  → Silero VAD
  → Whisper
  → OpenCC s2tw
  → SRT/TXT 合併
  → quality/review
  → Owner 人工驗收
  → desktop_outputs 交付
```

## 各階段

1. **輸入與穩定性檢查**：把使用者自己的影音複本放入 `input_audio` 邏輯輸入區，等待檔案穩定後建立一次處理工作。原始媒體只作為來源證據，不在流程中改寫。
2. **5 分鐘分段**：將長媒體切成固定 5 分鐘的實體音訊區段。每一段獨立處理，並保留足以判斷是否完成的 checkpoint。
3. **Silero VAD**：每段先經 Silero VAD 過濾非語音，再交給辨識器。VAD 是必要關卡；缺少或不相符時應明確失敗，不得靜默退回無 VAD 路徑。
4. **Whisper**：辨識器只處理通過 VAD 的區段，產生帶有區段時間碼的候選文字。分段結果先保留為原始機器證據，不能直接宣稱內容正確。
5. **OpenCC `s2tw`**：原始文字與時間碼文字都經同一個 `s2tw` 出口轉為臺灣正體中文。正體化是格式出口，不是人工內容驗收。
6. **SRT/TXT 合併**：依區段順序合併結果，將區段時間碼還原為全片時間，重新建立連續 cue。SRT 是時間碼權威；TXT 可提供對應的時間碼版本或純文字版本，但兩者不得互相冒充。
7. **quality/review**：執行結構檢查與內容風險審查，保留原始證據與候選輸出。重複牆、幻覺樣板詞、異常 cue 或其他阻擋型疑點應標記為 blocked，並要求人工檢視。
8. **Owner 人工驗收**：Owner 對照原始媒體、時間碼與候選文字，決定接受、修正、重轉或退回。任何機器狀態、測試通過或檔案存在，都不能代替這一步。
9. **`desktop_outputs` 交付**：依本機設定選擇要交付到桌面的候選產物。交付只是產物分發，不是內容驗收；被標記 blocked 的審查結果仍須保持可見，不能在交付時被隱藏成通過。

## Checkpoint 與續跑

- 只有該區段的必要處理與輸出完整成功後，才寫入 checkpoint。
- checkpoint 必須帶有本次辨識設定的簽章；設定、語言或必要模型狀態不一致時，舊 checkpoint 不得沿用。
- 程序中止或視窗關閉後重新啟動，先檢查可驗證的已完成區段，再從第一個未完成區段續跑。
- 不完整、損壞或簽章不符的 checkpoint 應重新處理該區段，不得把部分結果當成完成。

## 區段修補

- 修補預設先做 dry-run，確認受影響的時間範圍與候選結果後才可套用。
- 正式套用前先備份原有 SRT；修補工具只寫回 SRT，不重建或反推正式 TXT。
- 修補後重新執行品質／審查流程，並由 Owner 再次對照原始媒體。
- 修補工具不得改變主流程的分段策略、checkpoint 契約或辨識安全關卡。

## Blocked 的意義

`blocked` 表示機器審查發現需要人工判斷的風險，不表示流程失敗，也不表示內容已通過。原始媒體、機器候選與審查證據都應保留；在 Owner 尚未完成人工驗收前，任何交付都只能標示為候選或待審，不得宣稱完成。
